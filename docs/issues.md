### [已决 2026-08-19] 「50 分钟」对应全部 12 家
- 涉及位置：`README.md` §1 考核项表 P0 行、§1.1、§6 阶段二判定标准
- 依据：2026-08-19 用户拍板。竞品口径未再追问，按最严格的解释取全部投标人。
- 决策：吞吐量指标按**全部投标人**计，本次即 12 家 228 次调用，总耗时 ≤ 50 分钟。
- 影响：约束条件为 `单次耗时 ÷ 并发路数 ≤ 13.2 秒`（3000 秒 ÷ 228 次）。
  按单次 30 秒计，并发需 ≥ 3 路；单次 60 秒则需 ≥ 5 路。
  **风险点从「调用次数太多」转移到「并发路数够不够」**，而并发受显存限制——
  T9 单点实测的重点相应改为：不只测单次耗时，要测并发 N 路时显存是否扛得住。

### [已决 2026-08-19] PDF 切分策略：编号定层级 + 相对满行宽定标题
- 涉及位置：`src/s1_ingest.py`、`README.md` §3 表格 S1 行、§3.3、§4 章节块契约、
  §5.3 页面⑤、§8 的 B8、`docs/findings-pdf切分探针.md`
- 依据：对 228 个真实 PDF（40.5 万行）的实测，复现脚本 `scripts/probe_pdf_structure.py`。
- 决策：
  1. **排除字号与加粗方案**——实测全部 PDF 单一字号 12.0pt、加粗行 0%，投标系统抹平了格式。
  2. 层级由编号形式给出（`第N章`=1 / `中文数字、`=2 / `N、`=3 / `N.N`=4 / `（N）`=5）。
  3. 标题判定：匹配编号形式**且**行长 < 0.8 × 该文档行长 P90（满行宽）。
     相对量、随文档自适应，符合 CLAUDE.md 的「魔数要归零」。
- 验证结果：每份 PDF 切出章节块中位 111 个、块字数中位 114 字，
  与 docx 路径的 301 字同量级，**`src/s2_locate.py` 不需要改**。
- 副产品：实测证明「固定第 N 级标题」聚合在这批文件上失效（单元字数 P90 达 23,003、
  最大 278,553），**反向加强了 §3.3 选「直接父章节」的依据**。
- 遗留（不阻塞，见下方 P1）：表格类内容被切成碎块、页眉页脚未剔除、
  换项目后规则是否成立未验证。
