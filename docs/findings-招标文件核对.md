# 核对结论：招标文件评标办法 vs 拆分评审项.xlsx

> 日期：2026-08-19
> 目的：确认 `拆分评审项.xlsx`（福莱通产出）里的评分项、分值、档位区间，
> 哪些来自招标文件原文，哪些是福莱通自己加的。这决定 S0 模块要不要做「自动定位评分表」。
> 方法：从 `招标文件.pdf` 抽取评标办法章节文本，与 xlsx 逐项正则比对档位区间。
> 结论可复现，脚本见本文末尾「复现方式」。

## 一、来源文件

| 文件 | 位置 | 说明 |
|---|---|---|
| 招标文件 | `原始资料/实际测试工程文件/济阳区实验高级中学项目工程总承包（EPC） 2/招标文件.pdf` | 247 页，无 PDF 书签，文本可直接抽取（非扫描件） |
| 拆分评审项 | `原始资料/实际测试工程文件/拆分评审项.xlsx` | 237 行 × 11 列，福莱通通过智能体拆分产出 |

评标办法表在招标文件的 **第 33~37 页**（技术标部分），
第 38 页起是资信标，不在本次范围。

## 二、结论

**1. 19 个评分项全部来自招标文件，一字不差。**

xlsx 的 `评分名称` 与 `评分描述` 两列，是招标文件评标办法表「评分项目」与「评审标准」
两列的原样摘录。19 项，技术标满分合计 **100.0 分**。

**2. 三档区间 19/19 与招标文件原文一致。**

每一项的表述模板都是：

> 评委根据投标文件情况分为一般、良、优，分别酌情得 X-Y 分、Y-Z 分、Z-W 分，
> 内容不全酌情扣分，若此条缺项不得分；相关标书内容在《某方案》中体现。

比对结果 19/19 一致。**「一般 / 良 / 优」这个三档结构和每档的分数区间，
是招标文件写死的评分规则，不是任何厂商的经验积累。**

（首轮比对显示 18/19，唯一不一致的「各专业施工图设计的安排、协调、时间保证措施」
是抽取误差：该项档位文本跨 p35/p36 分页，取文本窗口时读进了下一项的区间。
按跨页拼接后重核，实际为 `0.2-0.7 / 0.7-1.5 / 1.5-2`，与 xlsx 一致。
**教训：从 PDF 抽表格必须处理跨页续行，按页切会静默读串行。** 这条对 S0 实现有直接影响。）

**3. 福莱通新增的是「要素 / 二级要素 / 权重」三列，招标文件里没有。**

xlsx 比招标文件多出的部分：每个评分项拆成 4~5 个**要素**（权重和 = 1.0），
每个要素再拆 3~4 个**二级要素**（权重和 = 1.0），全表共 80 个要素、236 条二级要素。

这是把「一般/良/优」这种主观档位转成可加权计算的连续分数的手段，
也是福莱通所说「高中低逻辑是我们的经验」的实际所指。
**方法本身可复现，难点在要素拆得准不准。**

**4. 招标文件原文明确规定了评分项与投标文件的对应关系。**

每项描述结尾都有一句「相关标书内容在《某某方案》中体现」，
而投标文件目录里确实存在同名 PDF。这解释了为什么
`拆分评审项.xlsx` 的 `pb_item_guid` 与投标 PDF 文件名尾部 GUID 能对上——
**这个绑定是招标方在投标系统里预先定义的，不是我们推断出来的巧合。**

**补充核对（2026-08-19）**：既然已决定评分表由我方自产、不依赖这份 xlsx，
又单独验了一遍**不用 GUID 能不能对上**——用招标文件的评分项名与 PDF 文件名做前缀匹配，
结果 **19/19 唯一匹配**，未匹配的文件只有「封面」。
文件名被投标系统截断到约 14 字（例：`各专业施工图设计的安排、协调、`），因此必须用前缀匹配，
不能用全等。**结论：绑定不依赖 xlsx，GUID 只是加固手段。**

**5. 招标文件给出了两条项目级规则，适用于全部 19 项。**

- 「内容不全酌情扣分」
- 「若此条缺项不得分」

这两条对应 `docs/data-contract.md` 评分表结构里的 `rules` 字段。
第二条尤其重要：**它把「未命中 → 判 0 分」从系统的设计选择升格为招标文件的明文要求。**

## 三、对 S0 模块的影响

| 原设计（README §3） | 按本次核对应改为 |
|---|---|
| 从招标文件 PDF 里定位「真正的评分办法表」，机器抽候选 + 人工确认 | 评分表已由投标系统结构化输出（`拆分评审项.xlsx`），直接读；招标文件 PDF 仅用于人工核对与抽取项目特征摘要 |
| 评分项 → 114 个评审点的人工映射（T7）、映射配置文件 | 不需要。评分项与投标 PDF 由 GUID 直接绑定 |
| 「长得像评分表的表格不止一张，全自动定位不可靠」 | 该风险对本项目不成立；但若换一个不提供 xlsx 的项目仍然成立，需保留降级路径 |

**未解决**：本次的 xlsx 是福莱通提供的。正式交付时这张表由谁产出、
我方是否要具备从招标文件 PDF 自行生成它的能力——这决定 S0 是否仍需实现自动抽取。
已登记为 `docs/issues.md` 的 P0 项。

## 四、复现方式

```bash
python scripts/verify_scoring_table.py
```

该脚本读取上述两个文件，输出 19 行比对表与一致数。
比对逻辑：对每个评分项名称，在招标文件文本中定位，取其后 420 字，
正则提取前三个 `X-Y分` 形式的区间，与 xlsx `评分描述` 列提取的区间逐一比较。
跨页项需按 p35+p36 拼接后重核（见结论 2 的括注）。
