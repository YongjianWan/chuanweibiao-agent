# 界面与交互规格

> 本文件是「工程建设类技术标辅助评审系统」的**界面设计与交互逻辑规格**，对应任务 T5、T6。
> 项目背景、术语、架构在 `../README.md`（唯一入口）；页面展示的字段定义在 `data-contract.md`。
> 读本文件前需要知道的三件事：
> 1. 本次测试的核心考核项是**能否在 50 分钟内真实跑完 12 家 × 19 项 = 228 次评审**，
>    不是分数准不准（README §1）；
> 2. S0~S4 是五个处理阶段，S0 离线跑、S1~S4 现场跑并计时（README §1.1）；
> 3. 「未命中」（投标人没写此项，判 0 分）与「未评定」（系统没判出来，不记分）
>    是两件完全不同的事，界面上必须视觉可区分（README §3.6）。
>
> 本文件所有线框中的数字（字数、耗时、显卡型号、分数）除标注外均为**占位示例**，
> 不代表实测值或已确定的配置。
>
> **动手改界面之前，先读文末的 §5「已定的设计，不要改回去」。**
> 那一节列的十条都是已经拍过板、并且已经被改回去过至少一次的东西，
> 每条写明「不许怎么做」「为什么」「出处」。改之前先看，别再来一轮。

---

## 1. 界面设计的唯一硬约束

**客户会站在旁边盯着屏幕看，判断这是不是真在跑。**（依据：录音）

因此：进度必须实时、逐项滚动、显示当前正在评哪一项和已用时间。
**一个转圈的 loading 动画等于没做。** 这是产品硬需求，不是技术细节。

「实时」的判定标准：**每完成一个评分项，1 秒内必须出现在滚动区**；
滚动区连续 30 秒无新条目时，需显示当前正在处理的项目名与已等待时长，而不是让界面看起来卡死。

---

## 2. 技术栈

**尚未确定，见 README §8 的 B6。** 在确定之前，下面五个页面先做成不依赖后端的静态 HTML 原型
（假数据、可点击、可演示交互），用于确认交互逻辑并给出前端实现参照。
原型只需现代浏览器可打开，不引入构建工具。

## 3. 页面流

```
① 新建评审  →  ② 确认招标信息  →  ③ 运行监视  →  ④ 结果并排  ⇄  ⑤ 单项详情
                   （人工介入）
```

设计说明：

- **没有「对应评审点」下拉框。** 评分项与投标文件按名自动绑定（README §2.1），不需要人工映射。
  本页的人工职责收窄为**核对**：确认抽出的 19 项、分值、三档区间与招标文件一致。
- **哪些能改、哪些不能改，逐字段写死**（2026-08-20 明确，此前只写「可直接编辑」，
  前端与后端各自理解，已经来回改过两轮）：

  | 字段 | 可否编辑 | 为什么 |
  |---|---|---|
  | `criteria`（评审标准原文） | **只读** | 它是招标文件原文，是模型判档位的唯一依据。改它等于改考题。代码里以源为准，**不吃本地存档**——存档里若有旧值也必须丢弃 |
  | `tiers[].min` / `max`（三档区间） | 可改 | 抽取可能出错，人工核对是本页的主要职责 |
  | `name` / `max_score` | 可改 | 同上 |
  | `tiers[].desc`（档位说明） | 可改，**默认空** | **本项目招标文件没有逐档描述**，19 项统一只有一段共用的评审标准。这一栏是留给评审专家自己补的说明，**不是招标文件原文**，界面上必须标明来源，不得暗示它出自招标文件 |
  | `aspects` / `synonyms`（检索词） | 本页不展示 | 它们只影响 S2 检索，不影响判分，属离线准备物（README §1.1）。放进来会让本页看起来像在现场调检索，反而不好解释 |
- 评分表由 S0 从招标文件 PDF 抽取（2026-08-19 决策：我方自产，不依赖投标系统提供的 xlsx）。
  S0 是**离线**执行的（README §1.1），所以本页打开时评分表已经就绪，这一页做的是核对不是生成。
  `拆分评审项.xlsx` 只在开发期作为对照参考，不进入产品流程。
- **本页同时承担「离线准备物当场可核」的职责。** 客户现场会问哪些东西是提前做好的
  （README §1.1 划的作弊界线）。评分表、项目级规则、项目特征摘要三样都在这一页摊开、
  可对照招标文件原文、**除评审标准原文外可当场编辑**（可编辑范围见上面的字段表）——摊得开就不是黑箱。
  「打开对照」按钮要能直接跳到招标文件的第 33~37 页。
- 「绑定的投标文件」列显示每个评分项匹配到几家的 PDF。**出现 `n/12` 且 n < 12 必须拦下**，
  说明某家缺了该项文件，或文件名 GUID 对不上。
- 项目级规则来自招标文件原文，写入评分表的 `rules` 字段，注入每次 S3 调用。
- 项目特征摘要（README §3.4）在此页确认，它决定了模型能不能判「针对性」，值得人扫一眼。
  上图摘要为占位文本，不代表 S0 的实际输出。
- 商务标不在本流程内，招标文件里技术标和商务标是各自独立的评分表。
- **换项目时若拿不到结构化评分表**，本页需退回「机器抽候选表 + 人工选定 + 人工映射评审点」
  的旧流程，见 README §2.1 的降级路径说明与 `issues.md` P0。

设计说明：

- 逐条滚动、带时间戳、带结果，这是「真在跑」的证据。
- 显存和 token 数实时显示，因为这是本次测试的核心考核指标（README §1），当场就给客户看，
  不用等报告。
- **token 数必须标注「本地估算」四个字**（2026-08-20 拍板）。B2 选定的智能体工厂端点
  `usage` 字段恒为 `null`，拿不到真实 token，现按中文约 1.5 字/token 本地估算。
  **不得把估算值当作端点返回值显示**——那是 README §1 门槛线上的事。
  报告里同样要写明这一句，见页面④的 `compute_notes`。
- **显存与卡型号是「有则显示，无则留空」。** 端点为远程托管，我方进程内取不到显存占用，
  只能拿到耗时。取不到时该栏显示「未采集」并在报告中注明原因，不要伪造数值，
  也不要因此把这一栏从界面上删掉——数据源一旦具备就直接填进去。
  **算力归属已定为「神思自有算力」**（2026-08-20 拍板，README §8-B3），卡型号与显存仍未定。
- **并发路数是可配项，不写死 8。** 2026-08-20 端点实测 12 家**串行**约 7.5 分钟，
  50 分钟预算富余约 6.7 倍，并发不再是达标的必要条件。界面照实显示当前实际路数，
  串行时就显示 1 路——显示一个跑不到的数字，客户当场一问就穿帮。
- **重试和未评定必须显示出来，不能藏。** 藏了反而像作弊；显示出来是系统诚实的证明。
- 进度分母 = 投标人数 × 评分项数。本次为 **228 = 12 家 × 19 项**。
- 本页覆盖 S1~S4 全过程。计时从页面①点「下一步：解析」起算，本页显示的「已用」与之连续。

│    0  = 该家没有这个文件，确实没写（miss_reason=no_file）    │
│    0⚠= 文件在但没检索到，可能是系统漏了（not_found）         │

设计说明：

- 并排展示供专家自己比较，**系统不产出跨家对比判断**（README §0 已定）。
- **12 家 × 19 项在一屏内放不下**，表格需横向滚动，评分项列固定不动。
  上图分数为占位示例，不代表任何实际评审结果。
- **`0` 和 `—` 必须视觉可区分**：前者是投标人没写，后者是系统没判出来。混淆这两者会误导评标。
- **`0` 自身还要再分一次，这是当天最容易解释不清的一格**（2026-08-20 明确）。
  判据是证据包的 `pool_sections`，数据层由评审结果的 `miss_reason` 给出
  （`data-contract.md` 第 6 节），渲染层必须照做：

  | `miss_reason` | 判据 | 含义 | 界面 | `confidence` |
  |---|---|---|---|---|
  | `no_file` | `pool_sections == 0` | 该家没有这个 PDF，**确实没写** | `0`，不加 ⚠ | 1.0 |
  | `not_found` | `pool_sections > 0`，或字段缺失 | 文件在、内容在，**是检索没找到** | `0` **必须带 ⚠** | 0.5 |

  为什么这一格不能省：`not_found` 自证不了到底是投标人没写还是我们没搜着。
  评委问一句「这家真没写吗」，我们答不上来。**把 `not_found` 画成一个干净的 0 分，
  就是把系统的失误算到投标人头上**，直接撞 README §1 的 P0「档位不能错」。
  2026-08-20 实测已把 `not_found` 压到 0/228，但机制必须在——换个项目它随时会回来。
- 未评定项不计入合计，合计旁用 `*` 标出该家有几项未评定。
- **专家改判不覆盖系统判分。** 系统判分是交付物主体，改判在单元格内以第二行小字并存，
  合计行同理出「系统 / 专家口径」两行；该家没有任何改判时专家口径行留空不显示。
  数据结构、合计算法与这条决策的三条理由见 `data-contract.md` 第 8 节。（2026-08-19 决策）
- **未评定项被改判后仍显示 `—`**，只有专家口径合计计入那个分。
  「系统没判出来」这件事不因为人补了分而消失。
- ⚠ 与 confidence 的定义、阈值 0.85 的算法见 `data-contract.md` 的「评审结果」。
- 分数是**区间内的连续值**（见 `data-contract.md` 评分表 `tiers`），显示保留一位小数。
- **同一评分项在全部 12 家判分完全无区分（落在同一档，含全部 0 分）时，整行标记「无区分度，建议复核」**：
  招标文件为该项设了分值，12 家专业投标人写出完全同档内容的概率，远低于
  「该项检索配错了」（全 0 是它的典型表现）或「该项的档位判飘了」的概率。
  数据来自报告数据的 `audit` 字段。
  **砍掉要素加权定分后，这是唯一一个能自动发现「档位判飘」的信号**，
  而判错档位是 README §1 的 P0 红线——所以这一行标记不能省，理由见
  `data-contract.md` 的 `audit` 字段说明。
- 「导出报告」输出 `data-contract.md` 的「报告数据」结构对应的静态 HTML，
  **必须包含 `compute_notes` 一节**（算力归属、卡型号显存、模型版本、技术做法）——
  竞品在政务云上测、我方用自有算力，这是对比时唯一的差异点，对外交付明确要求写清
  （依据：录音）。拿不到的字段填「未采集」并注明原因，不填估算值。
  已定的两条（2026-08-20 拍板，直接照抄进报告）：
  - **算力归属 = 神思自有算力**（卡型号与显存仍未定，未采集就写「未采集」）
  - **token 为本地估算**，报告里必须出现「端点 `usage` 恒为 null，token 由中文约
    1.5 字/token 本地估算」这句话，**不得把估算值当端点返回值列出**

│  要求的「针对本项目」。                                   │

│  ── 引用的证据（编号 0、2）──────────────────────        │

以上除档位区间与招标文件原文外，其余数值均为**占位示例**。

设计说明：

- 档位区间与那段引文来自招标文件原文，可直接照抄，不需要生成。
- **可解释性由「判分理由 + 引用证据」两块承担，没有加权算式那一块。**
  早先的设计里这里有一张「区间内定分（要素加权）」的表，随要素加权定分一并删除，
  理由见 `data-contract.md` 的「为什么不做要素加权定分」。
  客户要的是「哪项对应哪个得分点、偏差理由是什么」（依据：录音），
  判分理由写清「判哪一档、为什么是这一档、差在哪」就满足了，不需要凑一个加权算式。
- 「检索与置信度」这一块是**系统诚实度的展示位**：证据取了多少、有没有降级、有没有截断、
  重试了几次，一次说清。confidence 打折的原因在这里可以直接对上号，
  而不是只在页面④看到一个 ⚠ 却不知道为什么。
- **`上限` 那个数按评分项分值走，不是全项统一常数**，取自证据包的 `budget` 字段，
  直接显示即可，不要在前端重算。当前基准 4500、上下限 1500 / 9000
  （2026-08-20 由端点实测标定，原为 3000 / 6000），20 分项 9000、8 分项 6840、
  4 分项 3420、3 分项 2565、2 分项 1710。算式与上调依据见 `data-contract.md` §5。
- **未命中时这一块要显示「检索池 N 段」**，即证据包的 `pool_sections`。
  `N = 0` 说明该家没有这个 PDF，`N > 0` 说明文件在而检索没找到——
  这是专家判断该不该信这个 0 分的唯一依据，也是页面④那个 `0⚠` 点进来要看的东西。
- 引用原文由系统按 `cite` 编号从证据包截取（README §3.5），不是模型生成的文本，
  因此不存在「校验失败」这种状态。
- 「在原文中定位」按复合键 `(bidder, section_id)` 跳到投标文件对应位置并高亮。
  **只用 `section_id` 会跳到别家的标书**——12 家的 `id` 互相重复。专家不信任何不能溯源的判分。
  PDF 路径下按章节块记录的页码跳转到对应 PDF 页，切分方案见 README §3.7。
- 「专家复核」的改判记录要落库。这是 README §6 阶段三校准分数的数据来源，
  现在就埋点，后面才有东西可用。

- **「认可」也要落一条记录**，不是只有改判才落。「专家看过并同意」与「专家没看过」
  在阶段三校准里是两回事。记录结构见 `data-contract.md` 第 8 节。
- 本块的操作**不改变本页顶部的判分与页面④的系统分**，界面上要让这件事显而易见——
  所以操作区上方明写「系统判分 X 分（不因下方操作改变）」。

## 4. 不进主操作区的功能

页面③主操作区只放 README §5.3 线框里有出处的按钮（当前即「暂停」与「查看已完成结果」）。
**「重置运行」这类会让整轮 50 分钟归零的操作，放次级位置**（收进二级菜单或页面底部），
确认弹窗不能替代位置降权——现场手一抖点下去，弹窗只是多一次点击。
（2026-08-19 决策，起因是原型把「重置演示」与「暂停」并排放在了主操作区。）

## 5. 已定的设计，不要改回去

这一节不是设计说明，是**防回退清单**。下面每条都已经拍过板，其中多数在开发过程中被改回去过
至少一次——通常不是有人反对，是接手的人（或 AI）没有上下文，按「常识」把它改成了更顺手的样子。

**判定标准**：改动只要落在下表任意一行的「不许」列里，默认是错的。
确实要改，先改这一行指向的出处文档，写明新的理由，再改代码——**不要只改代码**。

- **页面③的实时滚动不能退化成 loading 动画。** 这是 §1 那条唯一硬约束，客户站在旁边看的
