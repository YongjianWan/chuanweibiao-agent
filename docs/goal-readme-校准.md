## 边界

- **可改**：`README.md`、`docs/` 下文档、`scripts/`、代码注释与 docstring
- **不可改**：`tests/` 下任何文件；`原始资料/` 只读
- **生产代码**：仅当与真相源 1 冲突且导致跑不通真实数据时可改
  （目前已知一处：`src/s1_ingest.py` 不支持 PDF）。其余记 issues，不擅自修

## docs/issues.md 格式

每条固定四段：

```
### [P0|P1|P2] 一句话问题简述
- 涉及位置：README §X / src/xxx.py:行号 / tests/xxx.py::测试名
- 事实：与哪条真相源冲突，冲突在哪
- 为何不能当场处理：缺什么决策、缺什么外部输入、谁能给
```

分级判据：
- **P0** 不解决则 README 无法自洽，或阻塞次日开发
- **P1** 重要但可在本次测试交付后处理
- **P2** 优化建议，不做不影响交付

## 完成标准（每条都要能当场核）

1. README 中每一个数字都能指到具体文件或出处；推算值明确标注「推算，未实测」
2. 「已知待改」表里九行全部处理完，逐行在变更摘要中说明改成了什么
3. `python -m pytest tests/ -q` 仍 13 passed
4. §10 的运行命令用真实文件跑一遍能跑通，或明确标注当前跑不通及原因
5. 冷读检查：开一个干净 agent，只喂 `README.md`，让它回答
   「这在讲什么」「每个术语什么意思」「我接下来做什么」，
   记录答不出或答错之处，改掉再交
6. `docs/issues.md` 中每条都有完整四段，P0 项数量在变更摘要中单独列出

## 停止规则

- 找不到 `README.md` 或 `原始资料/实际测试工程文件/` → 立即报告并停止
- 真相源 1 与 2 冲突且无法判断（真实文件行为与测试断言互斥）→ 记 P0，
  停在该主题，继续下一章节
- 需要业务决策的（如要素权重照抄还是自定）→ 记 P0，不自行决定

## 迭代方式

按 README 章节顺序逐节处理，一节一记变更点。
遇到不确定点写进 `docs/issues.md`，继续下一节，不在原地纠缠。
全部处理完输出：变更摘要（按章节）+ P0 清单 + `docs/issues.md` 路径。
